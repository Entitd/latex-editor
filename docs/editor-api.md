# Серверная часть редактора

Проекты — папки в `workspace/`, рядом с Laravel (`app/`). База данных для
проектов не используется. Настройки проекта сохраняются в `.latex-editor.json`;
этот служебный файл скрыт из дерева редактора. Существующие папки также видны
в списке проектов. Если главный файл не задан или больше не существует,
редактор ищет `.tex`-файл с `\begin{document}` и `\end{document}` в правильном
порядке, включая вложенные папки. LaTeX-комментарии при поиске исключаются.
При единственном кандидате он используется автоматически. Если кандидатов
несколько или ни одного, `settings.main_file` — пустая строка; перед сборкой
нужно выбрать файл явно. Движок по умолчанию — `pdflatex`.

Кнопка «Сделать главным» находится над исходником и у `.tex`-файлов в дереве.
Выбранный документ отмечается звездой. Явный выбор сохраняется в настройках
и имеет приоритет над автопоиском, даже пока документ ещё не дописан.

Откройте `/` или `/projects` для списка проектов. `/projects/{project}` открывает
редактор с деревом файлов, подсветкой LaTeX, сохранением (Ctrl+S), сборкой
(Ctrl+Enter), просмотром PDF и журналом. Перед сборкой открытый изменённый файл
сохраняется. Настройки проекта доступны по кнопке с ползунками рядом с названием.

В браузере маршруты списка и проекта возвращают страницы Inertia. Для получения
JSON отправляйте `Accept: application/json`. Остальные маршруты возвращают JSON,
кроме PDF. Маршруты используют
стандартную web-сессию Laravel и CSRF-защиту; для изменяющих запросов из браузера
нужен CSRF-токен.

## Проекты

| Метод | Адрес | Данные | Результат |
|---|---|---|---|
| GET | `/projects` | — | `{projects: [{name}]}` |
| POST | `/projects` | `{name}` | Создать папку, начальный `main.tex` и настройки |
| GET | `/projects/{project}` | — | `{name, settings, files}` |
| PATCH | `/projects/{project}` | `{name?, main_file?, engine?}` | Переименовать, изменить настройки |
| DELETE | `/projects/{project}` | — | Удалить папку проекта вместе с исходниками |

Имя проекта — один компонент пути, до 100 символов; поддерживаются кириллица,
пробелы внутри имени, буквы, цифры, `_`, `-`, `.`. Главный файл должен иметь
расширение `.tex`; поддерживаются вложенные пути, пробелы и кириллица в именах.
Пути задаются относительно проекта, компиляция запускается из его корня.
Движки: `pdflatex`, `xelatex`, `lualatex`.

## Файлы

Все пути задаются относительно папки проекта. Вложенные папки поддерживаются.

| Метод | Адрес | Параметры |
|---|---|---|
| GET | `/projects/{project}/files?path=main.tex` | Читать текст: `{path, content}` |
| POST | `/projects/{project}/files` | `{path, type: "file" или "directory", content?}` |
| PUT | `/projects/{project}/files` | `{path, content}` — сохранить, включая пустую строку |
| PATCH | `/projects/{project}/files` | `{path, new_path}` — переименовать/переместить |
| DELETE | `/projects/{project}/files` | `{path}` — удалить файл или папку рекурсивно |

Родительская папка должна существовать. Существующие пути не перезаписываются
при создании и переименовании. Выход за границы проекта и символические ссылки
запрещены. Чтение в редактор ограничено текстом UTF-8 до 2 МиБ. Загрузка бинарных
файлов пока не реализована. Переименование главного файла или содержащей его
папки обновляет настройки; для их удаления сначала выберите другой главный файл.

## Компиляция

| Метод | Адрес | Результат |
|---|---|---|
| POST | `/projects/{project}/compilations` | Запустить сборку с сохранёнными настройками |
| GET | `/projects/{project}/compilations/{id}` | Получить состояние и журнал |
| GET | `/projects/{project}/compilations/{id}/pdf` | Открыть PDF успешной сборки |

Компиляция пока **синхронная**: POST ждёт её завершения и возвращает HTTP 201
с описанием созданной сборки, даже если LaTeX завершился с ошибкой. Проверяйте
поле `status`: `success`, `error` или `timeout`. Ответ содержит `id`, `project`,
`main_file`, `engine`, время начала/окончания, `exit_code`, `log`, `pdf_url`.
Маршрут состояния позволяет повторно получить сохранённый результат.

Используются существующие Compose-сервис и скрипт `compiler/compile.sh`.
Контейнеру монтируется только выбранный проект в `/workspace` и отдельная
папка сборки `output/builds/{uuid}` в `/output`. Скрипт ограничивает компиляцию
60 секундами; вызов Docker ограничен 90 секундами. PHP-процессу нужен доступ
к Docker. Сборки хранятся независимо; автоматическая очистка пока не добавлена.
Переименование/удаление проекта не удаляет архивные результаты, но получить
их через старый адрес проекта после этого нельзя.

Ошибки запросов: 404 — путь/проект/сборка не найдены, 409 — имя уже занято,
422 — недопустимые данные, 413 — слишком большой файл, 415 — бинарный файл
или текст не в UTF-8.

## Проверка

`cd app && php artisan test --filter='ProjectEditorTest|CompilerScriptTest'`

Тесты используют отдельный временный диск и подменяют Docker-процесс:
пользовательские проекты не затрагиваются, реальный TeX Live не запускается.

`CompilerScriptTest` отдельно запускает настоящий Bash-скрипт во временных
папках с подменой `latexmk`: проверяет вложенные пути, кириллицу, кавычки
в именах, корректность JSON и отклонение недопустимых путей.
